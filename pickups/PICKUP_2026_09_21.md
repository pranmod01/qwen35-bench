4. **Benchmark code: config-driven runner** (`python run_bench.py <config> [--dry-run|--overwrite]`, `sbatch scripts/bench.sbatch <config> [--overwrite]`).
   - `bench/config.py` loads the YAML, expands (model × task × condition × seed), **refuses sizes a dataset can't supply** (the task code otherwise clamps silently), and records provenance.
   - `bench/models.py` holds `Qwen35Evaluator`, plus a `layer_variant` override of `layer_types` (random-init caveat documented in the README).
   - `bench/runner.py` loads each model once, writes one JSON per run to `results/<run_name>/<task>/`, and adds `response_distribution` to the metrics. Resume retries failed runs.
   - Evaluation wrappers (`bench/tasks/*_eval.py`, ported from vision-memory `eval_scripts/`): `afc_recognition_eval`, `continuous_recognition_eval` (not used in current configs),
     `pam_eval` (image–word paired associates), `serial_order_eval` (2-AFC). The naming `*_eval.py` was the user's choice, to avoid looking like duplicate task classes.
   - `bench/summarize.py` pools seeds per condition and reports accuracy, Wilson 95% CI, chance, above_chance and answer bias → `results/<run>/summary.csv`.
     Chance for paired associates is 1/n, since models answer with a studied word.
   - Bugs found and fixed: (a) the checkpoint's `eos_token_id` is 248044 while the chat template ends turns with `<|im_end|>` (248046), so generation ran into the next turn; the evaluator now stops on both.
     (b) The PAM parser took the `Word:` label as the answer (`'WORD: ANTLER'` → `word`); accuracy was unaffected, only the reported word.
