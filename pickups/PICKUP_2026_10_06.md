## Session 2 (started 2026-10-05 ~15:00; token-item version of the tasks)

### Completed (this session)

1. **Text version of recognition and serial order, with token-ID sequences as the stimulus.**
   - **Motivation (user):** an image enters the VLM as unlabeled visual tokens, so the text control
     must not use real words. An *item* is L random token IDs; old vs new is defined at the ID level.
   - **Design decisions (user):**
     - Option A: the text version is a `dataset: tokens` branch inside the existing `afc_recognition`
       and `serial_order` adapters, with the same prompts and forced-choice scoring. Image vs text is a
       config change. The user preferred a separate folder, so only the token-specific code lives in
       `tokens/` (see Key Files).
     - **Order counts:** an item is its exact ordered ID sequence.
     - **Foils `novel` + `recombined`.** `swap_k` and `permuted` are deferred.
       - `novel`: a fresh item sharing no token with the study list.
       - `recombined`: first half of studied item A + second half of studied item B. The correct
         option is a third studied item.
     - **Pool `clean`** (245,450 tokens), chosen so lists can reach max context. The user does not
       need the n grid to match the image runs.
     - **Item lengths 8, 64, 256.** 64 ≈ a Brady image (~66 visual tokens); 256 ≈ a THINGS 512 px image.
   - **Token pools** (`tokens/stimuli.py`, `POOL_SIZES`):
     - Removed from both: special/added tokens, partial UTF-8 (U+FFFD), any digit (the answer tokens),
       and any whitespace except one leading space.
     - `alpha` (104,164): letters only, ` ?[A-Za-z]+`.
     - `clean` (245,450): everything left.
     - All five Qwen3.5 sizes share one tokenizer (248,077 tokens, same vocab hash).
   - **No token is reused within an episode.** That caps a list's stimulus tokens at the pool size:
     `alpha` ~106k (40% of 262k context), `clean` ~249k. This is why `clean` was chosen.
   - **Items enter as IDs, not text.** Decoding 16 random tokens and re-tokenizing returned the same
     IDs in only 87/200 cases. `Qwen35Evaluator._prepare_inputs` stubs each `{"type": "tokens"}` item
     with a sentinel `<<<tokens:k>>>`, renders the chat template, tokenizes the text around the
     sentinels and splices in the IDs. It returns `input_ids`/`attention_mask`/`mm_token_type_ids`,
     the processor's text-only fields.
   - **Layout:** each item is preceded by `\n`, as an image is by its vision-start token. Prompts are
     the image prompts with "image" → "item" (`reword`).
   - **Trial records** keep `metadata` with `test_position`, foil source positions and both options' IDs.
   - **Serial order at n=27,000** would have listed 364M pairs in `balanced_sample_by_lag`.
     `sample_pair_by_lag` draws from the same distribution directly: a bin uniformly, a lag ∝ n − d,
     then the start position. It is checked against the reference's exact per-bin values.
   - **Checks:** `python tokens/test_stimuli.py` (CPU; needs `HF_HOME=$ZROOT/hf_cache HF_HUB_OFFLINE=1`),
     **8/8 pass**. The image configs' dry-runs list the same result files as before.
   - **Smoke**, job 13180850 (`configs/tokens/smoke.yaml` → `results/tokens_smoke/`, 0.8B, n=5,
     3 trials): 6/6 cells, no errors, bare-digit replies, choice mass 0.97–0.99.
